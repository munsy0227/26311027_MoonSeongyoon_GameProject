# 3주차 구현 및 제출 기록

> 과거 작업 기록이다. 테스트 명령·도구 경로와 캡처는 당시 자료이며 현재 제출 트리에 검증 도구는 포함하지 않는다. 최신 기준은 [Final.md](Final.md)와 루트 README이다.

확인일: 2026-09-13 / 학번: 26311027 / 이름: 문성윤

## 구현한 범위

- glc2d 실제 화면에 복도 배경과 서연 RGBA 이미지 적용.
- 시작/종료 버튼, Enter/Space 시작, 프롤로그 8개 대사와 서연 첫 대화 18개 대사.
- C1 선택지 2개, 각 선택의 서준·서연 반응, 공감 선택 +10점(중복 지급 방지).
- 구현 구간 완료 안내, 타이틀 복귀, 새 게임 상태 초기화.
- 윈도우 크기에 비례하는 4:3 출력과 1920×1440 기준 클릭 판정.
- 실행 파일 위치 기준 리소스 로딩, 빌드 시 resource 자동 복사, 누락 시 오류 안내.
- 이미지 원본과 기존 게임의 최종 기획을 유지. 이미지 출처는 사용자 직접 AI 제작으로 기록.

## 강의 PDF 전체 기준과 남은 작업

이번 요청인 그래픽 준비·화면 출력·게임 시작 구현은 위 범위로 완료했다. 강의 PDF의 3주차 전체 기준에는 다음 미완료 항목이 있으므로 전체 만점 요건 완료로 표시하지 않는다.

- MP3 5개 준비 및 용도 확정 완료. 시작·대화 BGM과 선택 효과음 연결 완료. 출처·사용 조건은 `doc/ResourceList.md`에 기록했으며 전투 BGM·공격·회복 효과음 연결은 후속 구현 범위다.
- 교실·그림자 이미지의 후속 장면 연결, 복도 조사·단서·장애물·전투·최종 결과 진행 구현.
- 최종 단계 전체 클래스/기능 구성 확정. 최신 구현 클래스 명세는 doc/게임기획서.md 17절에 추가했으며 기존 2주차 PDF는 갱신하지 않았다.
- 이전 테스트 이미지 정리 여부 검토. 원본 보존을 위해 이번 작업에서는 삭제하지 않았다.

## 사운드·폰트 후속 적용

사용자가 교체한 `resource/font/에이투지체-6SemiBold.ttf`를 실행 중에만 등록하여 전체 게임 텍스트에 적용했다. 폰트는 SIL Open Font License(OFL) 1.1 조건과 출처를 `doc/ResourceList.md`에 기록했다. 새 메인 BGM과 클릭 효과음을 시작·대화 진행·선택·타이틀 복귀에 연결했고, 전투 BGM·공격·회복 효과음도 프로젝트 리소스로 등록했다. MP3 원본은 유지하고 빌드 출력에만 영문 별칭을 사용한다.

후속 변경의 Debug x64 빌드와 기존 대화 분기 테스트가 통과했다. `runtime/font_start.jpg`는 폰트 교체 전 주아체 상태의 실행 기록이며, 현재 소스는 에이투지체를 사용한다. 스피커 출력의 청취 검증은 별도로 하지 않았다.

이 후속 변경은 아직 `w03` 태그와 원격 저장소에 반영하지 않았다.

- 전투 BGM: `Iwan Gabovitch - Dark Ambience Loop.mp3` → `bgm_battle.mp3`.

전투·공격·회복 음원은 후속 기능 연결 전 준비 상태이다. 원본/실행용 음원 파일의 출처와 사용 조건은 `doc/ResourceList.md`에 기록했다.

## 대사 확장 (최신 구현)

첫 만남 이후를 시나리오 1부 전체와 2부 장면 5~6까지 연결했다. 위의 첫 만남 완료 안내는 이전 구현 기록이다. 현재 마지막 지점은 실제 전투 직전이며 전투 승리나 최종 결말을 임의로 처리하지 않는다.

- 원본 대사 139개, 시스템 안내 포함 142개 표시 페이지, 진행 블록 19개.
- C1 공감 → O1 보관함 → O2 깨진 바닥 → I2 사고 기록 → C2 공감의 다섯 선택.
- 열쇠 자동 획득, 사진·사고 기록 보유 상태와 조건 대사, 선택별 점수, 위험한 바닥 HP -20.
- 전투 전 최대 점수 100, HP 100 또는 80, 핵심 단서 0~2개. 열쇠·사진·기록을 상단에 표시.
- 교실 진입 때 배경 교체, 그림자 대치 때 초상화 2개와 화자에 따른 밝기 구분.
- 마우스/숫자 선택과 방향키+Enter 선택 지원. 대사는 보수적인 너비로 두 줄 이내 분할.

`StoryData.h/.cpp`는 대사·조건·효과와 블록 연결, `StoryProgress.h/.cpp`는 진행·단서·보상 중복 방지, `ScenceGamePlay`는 입력·화면을 담당한다. `tools/build_story_data.py`는 기존 시나리오 표에서 데이터를 생성하며 전체 전투 전 대사의 누락·중복과 생성 파일 일치를 검사한다. 기존 소스와 생성 대사 파일은 CP949를 유지한다.

검증: Debug x64 빌드 통과, 원본 대사 일치 검사 통과, 32가지 선택 조합과 142개 페이지 도달 검사 통과. 조건 대사·보상 시점·중복 지급 방지·HP·초기화·마우스/방향키 입력·배경/인물 렌더 호출을 검사했다. 확장된 모든 장면의 실제 GUI 시각 검증은 아직 수행하지 않았다. 기존 runtime 캡처를 새 장면의 증거로 사용하지 않는다.

이 변경은 로컬 작업 트리에 있으며 커밋·태그 갱신·푸시는 수행하지 않았다.
