# 최종 구현 및 검증 기록

작업일: 2026-10-03 / 학번: 26311027 / 이름: 문성윤 / 최종 제출 태그: `final`

## 구현한 흐름

`Begin → Play(조사·대화 → 전투 → 후속·결말 대사) → Result → 새 게임 또는 종료`

전투 원고 B01~B28과 단서별 A/B/C 변형, 관계 대사 5개를 연결했다. 승리 후 D110~D116을 거쳐 좋은 G01~G17, 보통 N01~N12, 단서 부족 F01~F09로 분기한다. Life 소진은 승리 대사를 거치지 않고 L01~L07로 이동한다. 긴 대사는 두 줄씩 페이지로 나누며 원문 화자와 문장을 유지한다.

결말 화면은 좋은·보통·실패 3종이다. 실패는 단서 부족과 Life 소진의 제목·설명을 구분한다. 결과 장면에 들어갈 때 결말 종류·최종 점수·단서 수를 복사한다.

## 상태와 입력

- 결과·예고·관계 대사 출력 중 새 명령을 받지 않는다. 페이지 이동은 피해·보상을 반복 적용하지 않는다.
- 적 HP 0에서 승리 +20을 한 번 지급하고 반격을 차단한다. 적 HP·명령 UI를 숨기고 B22~B25의 퇴장 대사 뒤 공통 후속 대사로 진행한다.
- HP 0에서 Life를 한 번 감소시킨다. 피해 결과 확인 뒤 Life가 남으면 B26~B28, 없으면 Life 소진 결말로 진행한다.
- 관계 대사는 턴 피해 결과 확인 뒤 양쪽이 살아 있을 때 판정한다. 동시 충족 시 HP 50 이하 → 단서 활용 → 적 HP 40 이하 순서다. 조건별 출력 기록은 재도전 때 초기화한다.
- 재도전: HP·적 HP 100, 회복약 1개, 일반 공격 예고, 단서 활용 미사용. 점수·조사 단서·열쇠·차감된 Life는 유지한다.
- 패널을 여닫는 입력은 그 프레임에서 소비한다. 뒤쪽 대사·선택·전투에는 전달하지 않는다. 일시 정지 중 BGM은 유지한다.
- 결과에서 다시 시작하면 진행 상태와 결과 선택 위치를 초기화한다.

## 구조

| 구성 | 최종 역할 |
| --- | --- |
| CApplication | Begin/Play/Result 수명·전환, 새 게임, 결과 전달, BGM 전환 |
| StoryData / StoryProgress | 대사·조건·블록 연결, 조사 상태, 결말 판정·완료 |
| BattleProgress | 전투 효과·승패·재도전, 대사 페이지·단서 반응·관계 출력 기록 |

기존 소스·헤더를 확장했다. 새 패키지나 리소스는 추가하지 않았다. `.vcxproj` 등록을 확인하고 누락된 StoryData·StoryProgress의 `.filters` 등록을 보완했다. C++ 소스는 CP949를 유지했다.

## Windows 확인표

선택 순서는 C1 첫 대화 → O1 보관함 → O2 바닥 → I2 기록 → C2 두 번째 대화이다. A는 첫 번째, B는 두 번째 선택이다. 단서가 있으면 `단서 → 공격 → 공격 → 공격`으로 승리할 수 있다. 단서 0개·HP 80에서도 `공격 → 공격 → 회복 → 공격 → 공격 → 공격`으로 승리할 수 있다. 명령 사이에 결과·관계·예고 대사를 끝까지 확인한다.

## 제출 상태

최종 안내는 `final`이다. 기존 `w04`는 삭제하거나 이동하지 않는다. 과거 주차 문서는 당시 범위·검증 기록이다. 최신 기준은 이 문서와 기획서 19절이다. 소스 구현은 기능별 로컬 커밋에 기록했다. 태그 생성·원격 푸시·과제 제출은 수행하지 않았다. 사용자가 final 태그 생성과 푸시·제출을 진행한다.
