## 구현한 규칙

| 항목 | 현재 동작 |
| --- | --- |
| 적 | HP 100. 일반 공격 15 / 강한 공격 25를 번갈아 예고, 일반 공격부터 시작. |
| 공격 | 적 HP -20. |
| 방어 | 이번 적 피해를 10으로 줄이고 해제. |
| 회복 | 회복약 1개 소비, HP 최대 30 회복. 최대 HP 또는 약이 없으면 사용 불가. |
| 단서 | 1개 이상 보유 시 적 HP -40, 전투 시도당 1회. 단서는 소모하지 않음. |
| 결과 표시 | 플레이어 효과 확인 후 적 행동을 한 번 처리. 결과 출력 중 새 명령 금지. 실제 적용 피해·회복량 표시. |
| 승리 | 적 HP 0이면 반격 없이 +20점 한 번 지급, 전투 명령 숨김. |
| 재도전 | HP 0에서 Life 1개 차감. Life가 남으면 확인 입력 후 HP 100, 적 HP 100, 회복약 1개, 단서 활용 미사용, 첫 턴으로 복원. 조사 점수·단서는 유지. |
| 실패 | Life 0이면 추가 전투 행동을 차단하고 타이틀 복귀 안내. |
| 사운드 | 전투 BGM 전환, 공격·피해 및 회복 효과음. 승패 확정·타이틀 복귀 시 이야기 BGM으로 복귀. |

전투 명령은 숫자 1~4, 위·아래 + Enter 또는 버튼 클릭으로 고른다. 결과는 Enter/Space, 다음 버튼 또는 대화창 클릭으로 확인한다. 사용 불가 명령은 이유를 표시하고 턴을 소비하지 않는다. Esc/타이틀로는 기존처럼 타이틀에 돌아가며 새 게임은 모든 진행 상태를 초기화한다.

## 밸런스 변경

사용자 동의를 받아 적 공격 피해를 **20/40 → 15/25**로 변경했다. 나머지 전투 수치는 유지한다.

기존 수치로는 단서 0개인 경로에서 HP 100으로 재도전해도 승리 전략이 없었다. HP 80으로 시작하는 경로도 첫 시도에서 승리할 수 없었다. 변경 후에는 32가지 조사 선택 조합 모두 첫 전투 시도에서 승리할 수 있는 명령 순서가 존재함을 상태 탐색으로 확인했다. 모든 명령 조합이 승리를 보장하는 것은 아니다.

예를 들어 HP 80·단서 0개에서는 `공격 → 공격 → 회복 → 공격 → 공격 → 공격`으로 HP 15를 남기고 승리할 수 있다. 단서 부족에 따른 최종 결말 실패 조건은 유지하며, 최종 결말 자체는 후속 구현 범위이다.

## 구조

- `BattleProgress.h/.cpp`: 창·그리기·사운드에 의존하지 않는 전투 상태와 규칙.
- `ScenceGamePlay`: 기존 `StoryProgress` 완료 지점에 전투 연결, UI·입력·효과음.
- `CApplication`: 전투 상태에 따른 BGM 전환.
- `Player`·`StoryProgress`·`StoryData`: 기존 코드 유지.
- 새 C++ 파일을 Visual Studio 프로젝트와 필터에 등록했다. CP949 소스 인코딩을 유지했다.

## 검증

- Debug x64 빌드 통과. `Path/PATH` 중복 환경변수는 빌드 자식 프로세스에서만 정리했다.
- 실제 `BattleProgress`·`Player`·`StoryProgress`·`StoryData`를 컴파일한 C++ 규칙 검증 통과.
- 32가지 대화 선택 조합 각각에서 전투 도달, 첫 시도 승리 전략 존재, 승리 +20점, 3회 HP 소진과 Life 0 실패, 재도전 초기화를 검사했다.
- 회복·단서 사용 불가 시 무효 처리, 결과 확인 중 명령 차단, 방어 1턴 제한, 회복 상한, 적 HP 0에서 반격 방지, 승리 보상 중복 차단, 새 전투 초기화를 검사했다.
- 검증 코드와 빌드 산출물은 프로젝트 밖 임시 폴더에서 실행했다. 제출 트리에 `tests`·`tools`를 추가하지 않았다.
- `git diff --check` 통과.
- 실제 게임 창에서의 화면·마우스 조작·음원 청취 검증은 수행하지 않았다. 빌드와 규칙 검증을 GUI 검증으로 간주하지 않는다.

## 후속 작업과 제출 상태

전투 중 관계 변화 대사, 승리 후 본편 대사, 좋은/보통/실패 최종 결말 화면, 아이템 목록과 일시 정지 메뉴는 아직 미구현이다. 현재 승패 안내는 4주차 전투 구간의 종료이며 게임 전체의 최종 결말이 아니다.

변경은 로컬 작업 트리 상태이다. 커밋·태그 생성·원격 푸시·과제 제출은 수행하지 않았다. 이번 제출 시 생성할 태그는 `w04`이다.
